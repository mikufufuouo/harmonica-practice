# 稳定决策与重审条件

记录跨阶段需要记住的“为什么”；当前完成情况只看 [STATE](STATE.md)。2026-09-14 建立，历史版本由 Git 保存。用户新要求和新证据可以修订这些决定。

| ID / 状态 | 决定与原因 | 依据 / 何时重审 |
|---|---|---|
| D01 / 产品约束 | 以孔位与 B/D 为交互语言，目标与检测分开；先验证单孔控制再做整首评分 | 用户能吹旋律但容易串孔；同音无法唯一确认孔位。实机训练反馈可调整交互，不能把意图当检测 |
| D02 / 隐私约束 | local-first；音频默认不上传/不持久化，用户素材不进公开仓库 | 用户明确偏好。未来可选云端识图须明确选择图与服务，不能默认启用 |
| D03 / 待实验路线 | 比较单音 H1 与相邻多孔 H2/H3 的谐波/模板拟合，保留 uncertain；不凭主频或峰数判纯净 | [架构研究与局限](ARCHITECTURE.md)、[真实留出实验](EXPERIMENT.md)。尚无实吹证据；真实误报、弱邻孔或设备表现决定校准/限定范围/改路线 |
| D04 / 数据契约 | 实际音高 + 时间 + 独立歌词构成 NoteSequence；BD/MIDI/XML/简谱/音频仅来源适配器，未知节奏保留未知 | 用户要求长期统一谱面；[NOTE_SEQUENCE](NOTE_SEQUENCE.md)。新增格式暴露表达缺失时版本化迁移，不将来源格式变成歌曲底层 |
| D05 / 数据契约 | 原谱琴调用于 BD 解码；目标琴调只生成指法；移调显式且不改原曲，同音保留候选 | 源琴调和歌曲调不同，2D/3B 同音；`4367a70` 测试覆盖换琴/移调/原生无 BD 歌曲。新布局/压音按配置扩展 |
| D06 / 分期选择 | 图片原图旁人工校对 + 本地谱库先行；再试本地 OCR + 分区/规则，难图视觉模型后评估 | 用户主要拿公众号 BD+歌词图片；先降低校对遗漏风险。[IMAGE_IMPORT](IMAGE_IMPORT.md)。OCR 精度/速度/修正时间均待真实样例，不因输出合法就自动确认 |
| D07 / 工程选择 | Vite/TypeScript 原生 UI；AudioWorklet 轻采集、未来 Worker 共享离线/实时 DSP，暂不引入后端/大模型 | 小增量便于验证，避免主线程阻塞；复杂度或实测性能有证据后再加框架/WASM，不能为重写而重写 |
| D08 / 已授权部署 | 提前交付 PWA 外壳，公开 GitHub Pages 持续部署，SW 不强制中断当前采样 | 用户要手机测试并明确同意公开。缓存外壳不等于已验收手机音频；更新体验有真实问题再调整激活策略 |
| D09 / 工作约定 | Astra 设计/review，Terra 或 Luna 编码；一轮一个可验收增量；当前状态单页覆盖，Git 保留过程 | 用户要求跨新对话低成本接续；[AGENTS](../AGENTS.md)。若上下文仍漏项，补最小字段，不堆聊天转录/重复 handoff |

补充决策时只写跨阶段影响；实现细节留源码和专题契约。研究结论与出处保留在对应专题文档，无须每轮重抄。
