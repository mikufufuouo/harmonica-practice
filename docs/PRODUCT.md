# 口琴练习：产品决策与阶段路线

日期：2026-09-14。负责人：主代理；实现：Terra。本文是当前决策，阶段门槛通过后再扩大范围。

## 产品成立的标准

让一个靠 BD 谱吹旋律的初学者，每次拿起口琴练 5 分钟，都知道刚才是否稳住了单孔，以及下一次该练哪里。主要语言是孔位和 B/D（B 吹、D 吸），频率和音名放在诊断详情。先帮助建立单孔控制，再练整首。

最重要的假设：在用户自己的琴和主要设备上，浏览器可以以足够低的误报率发现明显相邻串孔，并在证据不足时明确显示“不确定”。不能把目标音命中当作单孔纯净，也不能把未检测到第二音当作纯净证明。

当前未知：琴的调性/型号/是否标准 Richter、主要设备和浏览器。实验版本默认 C 调标准 Richter，界面须提示确认；未知配置的样本不能混入已确认样本评估。

## 交互方向

横屏优先、竖屏仍可操作，不强制锁定横屏。上方是目标 BD 和短句；中央是 1–10 孔，B/D 两行；下方是一句可执行反馈。用目标轮廓与检测填充区分“想吹的”与“听见的”，不能用同一高亮混淆。

最终实时状态：等待吹奏、较像单孔、疑似串孔、不确定、输入质量不足。相邻孔只有在有证据时亮起，并带“疑似”；禁止把模板权重显示成口腔气流比例。颜色之外同时提供文字/符号。

第一种练习是短持音：选 4B，吹约两秒，停下看反馈，再试一次。先保持目标由用户选择，缩小推断范围；自由吹奏的自动定位放后面。同音歧义显示候选，如 2D/3B，谱面可以提供上下文，不能伪称麦克风已确认吹吸动作。

## Roadmap 与阶段门槛

| 阶段 | 用户能得到什么 | 做什么 | 验收与下一步 |
|---|---|---|---|
| 0A，本次 | 可在电脑本地打开的采样实验台 | 横向虚拟琴、调性设置、真实麦克风、短音采集、回放、WAV/元数据导出；不做识别 | 构建/类型/关键数据测试通过；权限、停止、回放互斥、标签可审查；真人采样仍需用户设备验证 |
| 0B，关键技术验证 | 一份有真实数据支持的“能识别到什么程度”结论 | 从 4–6 孔开始收集对照；离线重放比较单基频基线、受约束谐波模型、校准模板模型 | 按 EXPERIMENT.md 的真实留出录音指标验收；不通过则改善样本/限定设备/改交互，不开始练习评分 |
| 1，单孔教练 | 每次 3–5 分钟持音和相邻孔切换练习 | 本地实时推断、稳定反馈、设备质量提示；首先支持已验收的调和音区 | 主要设备至少三次独立真实练习；反馈可理解，误报/覆盖率/延迟过门槛；用户能依据提示调整动作 |
| 2，BD 跟练 | 输入短 BD 谱，慢慢吹完并回看问题 | 文本解析、当前/前后音、等待正确音模式、逐事件记录、短句复练 | 同音重复需新起音/显式推进；错音不跳过；不确定不算正确；预设案例与真人短曲验证 |
| 3，训练报告 | 知道哪几个 BD 音值得再练 | 分开统计目标命中、单孔证据、节奏、输入质量；每条建议可回溯对应事件 | 人工核对事件与分母；不确定比例必展示；只推荐有足够样本的问题，不用单个综合分掩盖原因 |
| 4，长期使用与 PWA | 安装、离线练、查看个人进步 | IndexedDB 版本化存储、备份/删除、离线缓存、更新提示、能力画像 | 飞行模式重开、升级不丢数据、导入导出往返；手机/平板/电脑实机生命周期与权限测试 |

安装与离线外壳也可在阶段 1 确认主要设备后提前；它不是判断识别可行性的前置条件。不按日历承诺算法完成时间，按证据推进。

用户随后明确主要来源其实是公众号 BD+歌词图片。图片路径提升为优先谱面入口：统一数据与文本基础 → 原图旁人工校对及本地谱库 → 本地 OCR 辅助 → 已确认歌曲跟练。文本入口保留用于手工录入和纠错。歌词行与音符引用独立保存，OCR 输出必须经过确认。分期与技术对照见 [IMAGE_IMPORT.md](IMAGE_IMPORT.md)。

## 报告口径，提前约束未来实现

- 目标命中率：可判定事件中命中目标音的比例，同时报告全部目标数、遗漏数、不可判定数。只命中同音候选但孔位未确认要单列。
- 单孔稳定占比：满足单孔证据门槛的可判定稳态时长 / 可判定稳态时长；另报可判定时长 / 全部有效吹奏时长。不是物理“纯净百分比”。
- 串孔：按一次连续事件计数，记录目标、候选邻孔、持续时间、证据质量；同一长音的几十帧不能当几十次错误。
- 能力画像：每个 BD 展示样本数、最近练习时间、近期趋势与不确定性。建议门槛起点为跨三次练习至少十次可判定尝试，届时再校准。
- 无节拍信息的简单 BD 谱不评分节奏。故意和弦、压音、超吹不纳入当前“串孔错误”定义；要有明确不支持状态。

## 职责与下一次交付

主代理负责方案、算法实验解释、范围控制、review 和阶段批准；Terra 每次只接一个可验收的实现包。代码通过不等于算法通过；合成数据通过不等于实吹有效。

本次结束在 0A：交付可运行实验台、设计及采样协议。下一包是可重复的离线评估工具与候选算法，须依据已获取样本调整；不连续自动做完整产品。

上述初始计划之后已按用户要求提前交付 PWA 并部署到公开 GitHub Pages。当前新增谱面数据层与 BD 导入预览；下一阶段仍需真实口琴样本推进音频实验，谱面格式适配不作为串孔识别已通过的证据。
