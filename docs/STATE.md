# 当前状态与下一步

更新：2026-09-14。应用代码基线：`4367a70`；本次仅整理项目工作流和文档。此页覆盖更新，历史看 Git。

## 项目是什么

个人 10 孔口琴练习 PWA，面向能看 BD 吹旋律、但难确认单孔的初学者。横屏优先，以真实孔位与 B/D 交互，最终提供跟练和有依据的训练建议。核心未证实问题是如何区分单孔泛音与相邻多孔，不能用命中主音代替纯净判断。

实际主要谱源是公众号 BD + 歌词图片。歌曲底层为与乐器无关的 NoteSequence，BD 是导入格式与派生指法；图片先人工确认再进本地曲库。具体原因见 [DECISIONS](DECISIONS.md)。

## 已交付与尚未实现

- 音频 0A：虚拟口琴意图选择、麦克风 PCM、最多 5 秒采样、取消/回放、WAV + 元数据主动导出。音频仅内存；没有 pitch detection 或串孔识别。
- 谱面 S0：统一歌曲 schema/运行时校验、严格 BD 自然音文本解析、独立未对齐歌词行、原曲 JSON 导出；C/G/A/D/F/Bb 标准 Richter 自然音指法、同音候选、显式移调且不改原曲。
- PWA：安装清单/图标、离线外壳、相对子路径、公开 GitHub Pages 持续部署。无账号/后端。
- 未实现：图片选择/校对、OCR、草稿确认状态机、IndexedDB 谱库、JSON 文件导入 UI、其他格式解析器、跟练、演奏报告和能力画像。schema 能表达不代表功能已交付。
- 技术栈：Vite + TypeScript 原生 DOM，AudioWorklet 采集。Worker DSP 为后续设计；依赖及命令以 package.json/lock 为准。

## 当前问题 / 未知

- 用户琴调、型号/是否标准 Richter、主要手机与浏览器未知；界面默认值不能替代用户确认。
- 真机需验证录制→回放→导出、横竖屏、安装/离线及后台中断。采集以 2048 样本批次传递，开始/结束含调度偏差，不能用它直接测精确起音延迟。
- BD 解析仅支持已列出的自然音语法；复杂混排、压音/延音等会报错，不能宣称兼容所有公众号。
- SW 不强制刷新，更新需在线访问后关闭所有该站点/PWA 窗口再重开。排查旧页面先确认版本与等待中的更新，勿直接归因部署失败。

## 下一包：S1a，原图旁人工校对并保存本地草稿

主代理先细化最小草稿契约，再派 Terra 实现、Luna 可承担独立 UI 小包；当前没有运行中的实现任务或必须恢复的临时会话。

- 交付：本地选图、原图旁逐行输入 BD/歌词、明确原谱琴调、诊断与人工确认、草稿刷新恢复。复用 NoteSequence，未知节奏不伪造。
- 验收：自造图完成录入→改错→逐行确认→刷新恢复；修改已确认内容使相关确认失效；错误/未知原谱调不能成为已确认歌曲；图片和文字无上传；主代理检查数据/交互，真实手机结论留待实测。
- 范围边界：本包不加 OCR、不做自动歌词对齐、不做跟练。S1b 再交付已确认本地谱库、JSON 备份往返和删除，合起来满足 IMAGE_IMPORT 的 S1 门槛。
- 真实代表图能帮助校验语法；未提供时可用自造图推进 S1a，但不能宣称已验证公众号兼容性。用户若反馈采样故障，优先修复可复现故障再推进本包。

音频线仍优先获取十余段真实试样检查采集链路，然后按 [EXPERIMENT](EXPERIMENT.md) 做 0B-1 离线评估工具及基线。缺真实音频不妨碍谱面独立增量，但阻止算法准确性验收；不绕过门槛进入评分。
